# Диаграмма кода — доставка команды до устройства

Критический путь продукта: пользователь нажал кнопку, устройство отработало. Здесь сходятся все принятые решения — приём команды любой репликой, очередь устройства, передача через Redis нужной реплике, выдача в висящий длинный опрос и срок годности команды.

```mermaid
%% C4 Level 4 — Code. Последовательность доставки команды
sequenceDiagram
    autonumber
    participant app as Мобильное приложение
    participant gw as API Gateway
    participant dcA as Device Control, реплика A
    participant dreg as Device Registry
    participant redis as Redis
    participant dcB as Device Control, реплика B
    participant hub as Домашний хаб
    participant mq as RabbitMQ

    app->>gw: POST /devices/{id}/commands
    gw->>gw: Token Verifier: подпись и срок
    gw->>dcA: проброс запроса
    activate dcA
    dcA->>dreg: GET /devices/{id}
    dreg-->>dcA: тип устройства и его возможности
    dcA->>dcA: Command Validator: команда допустима
    dcA->>redis: положить в очередь устройства, со сроком годности
    dcA->>redis: Replica Bus: уведомить владеющую реплику
    dcA->>dcA: Shadow Manager: желаемое состояние
    dcA-->>gw: 202, идентификатор команды
    deactivate dcA
    gw-->>app: 202, идентификатор команды

    alt Хаб на связи, висит длинный опрос
        redis-->>dcB: уведомление о команде
        activate dcB
        dcB->>redis: забрать команду из очереди
        dcB-->>hub: ответ на длинный опрос с командой
        deactivate dcB
        hub->>hub: перевод в локальный протокол, отправка устройству
        hub->>dcB: результат выполнения
        activate dcB
        dcB->>dcB: Shadow Manager: сообщённое состояние
        dcB->>mq: событие о результате команды
        deactivate dcB
    else Хаб офлайн
        Note over redis: команда ждёт в очереди устройства
        hub->>dcB: подключился, новый длинный опрос
        activate dcB
        dcB->>redis: забрать накопленные команды
        alt Срок годности не истёк
            dcB-->>hub: команда
            hub->>dcB: результат выполнения
            dcB->>mq: событие о результате команды
        else Срок годности истёк
            dcB->>dcB: отбраковка, отметка в истории команд
            dcB->>mq: событие о просроченной команде
        end
        deactivate dcB
    end
```

## Что показывает

**Приём команды не зависит от соединения.** Реплика A отвечает клиенту 202 сразу после того, как команда легла в очередь. Она не знает и не должна знать, доступен ли дом прямо сейчас.

**Передача между репликами.** Соединение с хабом держит реплика B, а команду приняла A. Связка «очередь плюс уведомление через Redis» решает это без привязки хаба к конкретной реплике на балансировщике.

**Длинный опрос работает как push.** Хаб почти всегда висит в ожидании ответа, поэтому команда уходит в дом практически мгновенно — даже когда приложение закрыто и WebSocket не поднят.

**Срок годности проверяется при выдаче, а не при постановке.** Команда, пролежавшая в очереди дольше положенного, до дома не доезжает: «включить свет в 22:00» не должно срабатывать в час ночи.

**Два состояния устройства обновляются в разные моменты.** Желаемое — сразу при приёме команды, сообщённое — только после подтверждения от хаба. Расхождение между ними и есть ответ на вопрос «команда отдана, а устройство офлайн».
